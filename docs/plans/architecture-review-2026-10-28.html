Problem. The rule is stated in C# once and in OTTL regex five times (span keep, log keep, three resource copies, metric deny); the contract test proves a substring is present, not that the two sides agree, and its own remarks say both sides were once wrong identically (finding 01).

Solution. Make the allowlist rules a module with one interface; the analyzer, the runtime processor and a collector emitter are three adapters at that seam.

  • locality: a family change edited once
  • leverage: one table, three adapters
  • tests compare emitted OTTL to rules, not substrings
  • delete ~8 copy-paste regex blocks
config.yaml header states the file is “written by hand rather than generated”. Worth reopening: the contract tests were written because drift is the failure; five copies make the substring check the weakest link.

Gather CouchDB host policy into one module

Strong in-process
  • RaksawiPipeline.cs — TryRedactCouchDbUrl (list Contains, ordinal)
  • AllowlistProcessor.cs — IsCouchDbSpan (OrdinalIgnoreCase)
  • CouchDbUrlPolicy.cs, RaksawiObservabilityOptions.cs
  • deploy/collector/config.yaml — ^couchdb(\.raksawi\.internal)?$
Before
HTTP enrich hook
host match: case-sensitive
disagree on “CouchDB” vs “couchdb”
AllowlistProcessor
host match: ignore case
Collector regex
third host list, hard-coded
After
CouchDB policy module
interface: Classify(Uri) → redacted | not couch · IsCouchSpan(tags)
host list · comparison rule · changes-feed test · path/query redaction (internal)
seam: collector regex derived from the same host list

Problem. The same fact — which hosts are CouchDB — has two comparison rules in-process. A host configured as CouchDB is not redacted (uri.Host is lowercase, list match is ordinal) yet the processor treats the span as CouchDB and admits url.full unredacted. Fail-open and fail-closed meet in the wrong order.

Solution. One module owns host matching, redaction and the span classification; hook and processor both call it.

  • locality: one comparison rule, one test
  • leak path closed by construction
  • RKS-style fail-open comments retire
  • tests hit one interface
Consistent with ADR-0023; verify the case mismatch on a real span before acting (the sample is safe: new Uri(...).Host is already lowercase).

Problem. One class finds assemblies, checks provenance and answers “is this key allowed”; the startup walk runs once per signal and the two processors repeat the same drop-and-count loop around it.

Solution. Discovery runs once behind a seam with two adapters already present (reflection, and ForDeclaredKeys in tests); verdict becomes a small module both processors share.

After
Governance analyzer

Problem. ADR-0028 makes a PascalCase log property vanish at export, and the sample’s own comment says one line was left undeclared on purpose — yet the publisher, repository and consumer logs carry undeclared placeholders and nothing at build says so.

Solution. Extend the build-time enforcement point to read message templates against the same verdict.

  • locality: key rule lives in one place
  • silent drop becomes a build signal
  • sample demonstrates what it teaches
Intent unclear: if those sample logs are meant to be dropped, the sample should say so; either way the gap is real. Template parsing is the cost — the analyzer is deliberately literal-only.
