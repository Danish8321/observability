# D0.2 access confirmation — before Run 0 starts

README (2026-08-28): "Confirm access before starting it, rather than assuming
it will go the same way [as D0.3]." Not yet done. ADR-0024 confirmed all five
D0.3 sources unreachable; D0.2 needs a separate check since its six signals
only partially overlap those five.

## Signals needed for Run 0, checked against ADR-0024's findings

| Signal | Source | ADR-0024 said (D0.3 source) | D0.2 status |
|---|---|---|---|
| HTTP request rate/latency, per route | IIS logs (`LogParser`) / Kestrel access logs | "no IIS host access" | unconfirmed — ask again, D0.2 needs log *files*, not host access |
| CPU, working set, allocation rate | Windows performance counters | not covered by D0.3 | unconfirmed — new ask |
| NATS message rate, per subject/consumer | NATS monitoring endpoint | "no NATS monitoring endpoint" | presumed blocked, same finding |
| CouchDB call volume | CouchDB `_stats` + HTTP access log | "no CouchDB admin access" | unconfirmed — `_stats` may not need admin; check separately |
| GC behaviour | .NET CLR Memory counters | not covered by D0.3 | unconfirmed — new ask |

Two of five are flat "no" per ADR-0024 (NATS monitoring, and IIS/CouchDB admin
access as stated). Three were never actually asked for D0.2's narrower need
(log files vs host access, `_stats` vs admin, perf counters).

## Ask (send to danish)

1. Can IIS/Kestrel access logs for the three Run 0 candidate services
   (`profile-api`, compliance-backend/Ocelot pairing, one more) be exported
   as files for a one-week window, without needing host access?
2. Can Windows performance counters (CPU, working set, GC) be sampled
   remotely or exported for those same hosts, even ad hoc?
3. Is CouchDB `_stats` reachable without full admin — a read-only or
   monitoring credential?
4. Confirm NATS monitoring endpoint is genuinely unreachable (ADR-0024
   already says yes) — no new ask, just carrying the finding forward.

## If all four come back "no"

D0.2 has no data source at all, not even a degraded one. That's a stronger
finding than ADR-0024's — worth its own ADR entry (D0.2 becomes unattainable
the same way D0.3's five-source sweep was), and the expiring-baseline framing
in `phase0/performance-baseline.md` needs to change: there is no baseline to
take, ever, not "not yet taken."
